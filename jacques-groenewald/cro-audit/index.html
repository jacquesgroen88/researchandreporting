Where the money leaks

Mobile is most of the traffic

Mobile usually converts at half to two thirds of desktop. The gap between the two is the cheapest revenue in the store, because the visitors are already there.

What to test first

Every idea is written as a full hypothesis and scored with PIE. The order changes as you change the numbers, because the scores come from where this store actually leaks.

Size the test before it runs

Stopping a test when the dashboard turns green is how programmes fool themselves. The run length is fixed before launch, from the traffic and the smallest lift worth detecting.

From first leak to lasting wins

Most conversion work fails at the start: tests picked from opinion, run on broken tracking, and stopped the moment the dashboard turns green. This process is built to prevent all three. Research takes the first two to three weeks, then the programme runs on a weekly rhythm.

Revenue per visitor leadsConversion rate alone can lie. A test that lifts conversion and cuts order value loses money. RPV catches it.
Two sources or it waitsA problem must show up in two of three places: the numbers, recorded behaviour, and what customers say.
Fix bugs, test doubtsSomething broken is not a hypothesis. Ship the fix and save test traffic for real questions.
Losers are lessonsEvery result is logged, because a losing test tells you what customers do not care about.
