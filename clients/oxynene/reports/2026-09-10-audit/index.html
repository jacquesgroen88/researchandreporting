Website Audit

What's working, what's costing you leads

The site has real field photography and a genuine client base — but the fundamentals a cold visitor and Google both judge you on are quietly broken.

Homepage H1 is literally "Home"
The page's actual H1 tag reads "Home" — the real headline ("We would be happy to provide you with more information or a free estimate") is buried in an image-box widget with no keyword value.
Set a real H1: "Pest Control in Centurion — Residential, Commercial & Industrial".
"Our Customers" testimonial carousel is broken
The homepage testimonial slider points to images hosted on the old staging domain (tidydesigns.co.za/Oxynene/...) which now 404. Every visitor sees a blank, broken carousel exactly where trust should be building.
Re-upload the testimonial screenshots to the live domain, or replace with a proper review widget.
Hero has no phone number or clear CTA
The homepage hero is a bare "Name / Email / Message" form with a button labelled "Send" — no phone number, no WhatsApp, no service-specific ask.
Add a tap-to-call number and a "Get a Free Quote" CTA above the fold.
Large, unoptimised images
Several homepage images (the "Untitled design" carousel) are 400–600KB PNGs used as photos — no compression, no next-gen format, actively slowing the page.
Compress and convert to WebP; target under 150KB per image.
6 of 8 homepage images have no alt text
Missing alt attributes hurt both accessibility and image-search SEO — a real cost given the strong photography already on hand.
Add descriptive alt text to every image (e.g. "Oxynene technician spraying residential driveway").
Genuine field photography exists
Unlike most small pest-control sites, Oxynene has real photos of technicians on real jobs — spraying, inspecting, using branded equipment. This is a real asset most competitors don't have.
A genuine institutional client base
The "Companies we worked with" logo wall (Pro Admin, Landstar, a municipality, a church body) is real social proof most residential-focused competitors can't show — it's just buried on the homepage with no context.

Analytics & Tracking

You can't optimise what you can't measure

Google Site Kit is installed with a generic GT- tag, but there's no confirmed GA4 conversion setup, no Meta Pixel, and no verified Search Console — meaning ad spend and organic traffic are both flying blind.

GA4 partially configured
A Google Site Kit tag (GT-55JKG4G) is present, but no confirmed conversion events (form submits, calls, WhatsApp clicks) are wired up.
Configure GA4 conversion events for form submissions, tel: clicks and WhatsApp clicks.
No Meta Pixel found
No fbq() tracking call detected anywhere on the homepage — any future Facebook/Instagram ad spend would have zero attribution.
Install Meta Pixel + Conversions API before running any paid social.
Search Console not verified
No google-site-verification meta tag found — Oxynene can't see its own search performance, indexing errors or query data.
Verify the domain in Google Search Console and submit the sitemap.
No heatmap or session recording tool
No Hotjar or Microsoft Clarity detected — there's no visibility into where visitors drop off on the site.
Install Microsoft Clarity (free) to see real visitor behaviour.
SEO Audit

Findable, but not for the right things

No meta description on any page checked
Homepage, About, Services and Contact all lack a meta description — Google is left to auto-generate snippet text, usually poorly.
Write a unique, keyword-rich meta description for every page.
No schema markup
No LocalBusiness or Organization structured data — Oxynene is invisible to rich-result features like map packs, review stars and knowledge panels.
Add LocalBusiness schema with NAP, hours, service area and service list.
"Centurion" and "Gauteng" barely appear
The homepage title and headline don't mention the service area — a searcher typing "pest control Centurion" has no on-page signal this is a local match.
Work "Centurion" and the wider Gauteng service area into titles, H1s and copy.
Sitemap exists and is discoverable
wp-sitemap.xml is correctly referenced in robots.txt.
